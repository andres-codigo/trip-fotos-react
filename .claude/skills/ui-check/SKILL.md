# UI check

Run the checklist in [Visual check for UI changes](../../../.github/instructions/testing.instructions.md#visual-check-for-ui-changes) for `$ARGUMENTS` (or the pages the diff can affect), yourself and without asking. That section is the single source of truth, shared with Copilot; do not restate it here.

Container specifics the section does not cover:

- No `chromium-cli` or Playwright is installed: run the committed capture script `cypress/ui-check/capture.cy.js`, never a throwaway spec. Start `npm run emulators`, then run `node .claude/skills/ui-check/affected.mjs`: it reads the branch diff through `cypress/impact.js` and prints the `UI_CHECK_ONLY` of the captures the change can affect (none means run them all). Run it once per ref with `FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099 FIREBASE_DATABASE_EMULATOR_HOST=127.0.0.1:9000 FIREBASE_STORAGE_EMULATOR_HOST=127.0.0.1:9199 UI_CHECK=true E2E_EMULATORS=true UI_CHECK_LABEL=<main|branch> [UI_CHECK_WIDTHS=390,1280;<capture>=390,768,1280] [UI_CHECK_ONLY=<capture ids>] node .claude/skills/verify/run-e2e.mjs`; give 768 and breakpoint widths only to the captures the change touches there. Before capturing `main`, run `node .claude/skills/ui-check/main-captures.mjs [widths] [only]`: exit 0 means the `main` folder already holds those captures of the current `main` commit with this capture script, seed data and widths, so skip it; exit 1 prints why and the `UI_CHECK_ONLY` that retakes just the missing ones. Recheck a fix or a script edit with `UI_CHECK_ONLY` on the branch alone. Screenshots land in `cypress/ui-check-captures/capture.cy.js/<label>/<capture>/`, outside `cypress/screenshots`, so a component or E2E run never deletes them; each capture replaces only its own folder, so run both refs before comparing. The run stops within a second when the emulator log shows a crash (`Unexpected rules runtime error`): restart the emulators.
- Extend the script (a new page or state) in the same change that needs it, rather than writing a one-off spec. Keep it ESLint-clean: lint errors make a spec fail to load ("Failed to fetch dynamically imported module").
- Port 3000 may be the user's own dev server: never kill it by port. Start your own Vite on another port and stop it by PID, or run the spec against the emulators (see [testing.instructions.md](../../../.github/instructions/testing.instructions.md#when-to-run-e2e-locally)).
- Never read `.env`: the seeded emulator accounts reach the spec through the Cypress config and `performLogin()`.
- Case-only file renames can leave files missing after `git switch`: `git restore` the affected folder, never anything with uncommitted work.

Before capturing, write down every page, state (dialogs, empty, loading, error, hover, focus, disabled, own/other record, admin) and width the change can touch, and capture all of them: the run is not finished while a reachable state is uncaptured, and "not checked" is for what is impossible, each with its reason, never for what was skipped. Compare with `node .claude/skills/ui-check/compare.mjs [main] [branch]`: it lists identical, changed, new and missing shots, the changed rows of each changed pair, writes a side-by-side crop (`main` left, branch right) to `cypress/ui-check-captures/compare/<branch>/`, and a sheet of each new or changed state with its widths side by side under `sheets/`; it compares only the captures the branch run took. Open every crop and sheet, and the full image where the crop alone does not show the context; for identical pairs open one image per page and state to confirm it rendered, since identical blank or spinner frames also hash equal. Report what is on screen for each image you opened. Hold the merge while a visual question is open, even when CI is green. Delete the branch shots and the crops afterwards; keep the `main` folder and `main.json` for the next check.

Run it before `/verify`, which refuses a UI change until this records `pass`: build, targeted tests, `/ui-check` and fixes (each with a test), `/verify` once, commit.

Status line: run `node .claude/skills/verify/reset-checks.mjs` and then `node .claude/skills/ui-check/status.mjs capturing` when the run starts, `reviewing` while you open the images, then `pass` or `hold` (a visual question is open). The status line shows it next to the `/verify` state.
